# User guide

Ultraglass provides a web form for running the network queries that an administrator has enabled. The available locations, query types, target validation rules, and result fields depend on the deployment configuration.

## Run a query

### Choose a location

Select the router or location from which the query should run. The location determines the network path and device that will execute the command.

Deployments with a small number of locations may show them as cards. Larger deployments usually show a dropdown.

### Choose a query type

- **Ping** tests reachability and reports round-trip time.
- **Traceroute** shows the path toward a destination and may include hop latency, packet loss, ASN, organisation, country, IXP, or reverse DNS details.
- **BGP route** shows routes for an IP address or prefix when the selected device supports the configured directive.
- **BGP community** finds routes associated with a community value.
- **BGP AS path** finds routes that contain one or more ASNs.

### Enter a target

Depending on the query type, enter an IP address, hostname, prefix, or ASN. Examples include `8.8.8.8`, `2001:4860:4860::8888`, `8.8.8.0/24`, `google.com`, and `AS15169`.

The deployment may restrict target formats or networks. A rejected target means the administrator's query policy did not allow it, not that the device is unreachable.

### Submit the query

Select **Submit** to run the query. The page shows the response when the device finishes, or an error message when the query cannot complete.

## Hostname resolution

When you enter a hostname instead of an address, Ultraglass can resolve it in the browser using DNS-over-HTTPS. The resolver returns available IPv4 and IPv6 addresses, and you choose which address to query.

<Callout type="info">Browser-based resolution means the Ultraglass server does not need to resolve the hostname on your behalf. The configured resolver determines which addresses are returned.</Callout>

1. Enter a hostname such as `google.com`.
2. Select **Submit**.
3. Choose an IPv4 or IPv6 address from the resolution dialog.
4. Confirm the selected address and run the query.

If no address is returned, check the hostname, the configured DNS-over-HTTPS provider, and any browser or network policy that may block the resolver request.

## Use My IP

The **My IP** control detects your public IPv4 and IPv6 addresses and offers them as query targets. It is useful when checking how a looking glass reaches your current network.

1. Select **My IP** beside the target field.
2. Choose the address version you want to test.
3. Submit the query as usual.

The detected address is the address visible to the configured detection service. It may differ from an address assigned to your device when you are behind NAT, a VPN, or a corporate proxy.

## Read results

The result panel may include raw device output, parsed tables, route metadata, AS path links, traceroute hop details, or a query error. Structured output is available only when both the deployment and the selected device support it.

Cached results show a cache indicator and the time at which the result was created. A cached response is still a response from a previous query. Run the query again when you need current device output.

## When a query fails

Check the target format first, then try another location if one is available. If the problem continues, report it to the operator of that Ultraglass deployment with the location, query type, target format, approximate time, and visible error message. Do not include credentials or private device output in a public report.
